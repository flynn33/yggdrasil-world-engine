# Bounded topology and five-axiom reference policy

Policy identity: YWE-TOPOLOGY-AXIOM-REFERENCE-001
Policy version: 1.0.0
Status: Active reference policy for YWE-REQ-0047, recorded by ADR-0038. Runtime acceptance is separate.
Authority: downstream YWE reference policy. This identity is not an upstream ASH rule ID. YWE-REQ-0047 governs this bounded reference realization.
Owner and partition: ywe_core.
Method pin: Raven Forge Development v0.7.0 at 87409bc36fb9d4782eab02189adb184f2b3962a7.

1. ReferenceTopologyGenerator and ReferenceAxiomEvaluator are cohesive, stateless, pure reference owners. Their explicit collaborator is the actual StateModel; they use only its public pure validate_diagnosis port through the StateModel-owned class implementation. They do not dispatch an instance-supplied method override. They perform no capture, clock, file, network, process, registry callback, live-session publication, mode change or materialization. Python is repository reference/testing tooling, not production application source. The shared validator is governed by YWE-REQ-0046 and belongs to StateModel/state_values.py. Each producer exposes class-owned configuration()->exact immutable tuple(source_binding,profile_binding,policy_binding) and validate_owned_result(result)->exact bool. A trusted construction token/cookie with exact issuer and result self identity proves configured local execution only; it adds no wire field, host/capture authentication, mutable per-result ledger or global registry. Publicly constructed, copied, foreign or corrupt results do not acquire producer capability.

2. Each request retains the complete immutable StateDiagnosis. The owner obtains current full-source/full-profile mathematical revalidation. Successful topology requires a parsed state, available current profile, VERIFIED diagnosis, VALID status and ALREADY_VALID normalization status. Axiom evaluation requires a parsed state, available current profile and VERIFIED diagnosis, but may evaluate measures attached to a non-VALID state. Its result never reclassifies that state as valid or operationally STABLE.

3. Topology depth is locally supported from 0 through 6 inclusive. The request represents an exact signed64 integer, allowing negative and excessive values to receive explained refusal without allocation. Entire requested expansion succeeds or fails; there is no partial frontier returned as complete. Depth six has 729 output leaves and 1,093 nodes constructed across all levels, including the root.

4. The seed token is an exact ASCII string matching [A-Za-z0-9_-]{1,32}; its explicit default is F. Root path_token is r. Continuation, positive and negative append 0, 1 and 2 respectively. node_id is topology:<seed_token>:<path_token>. Root parent_id is null. Every nonroot parent_id uses the same seed and the path without its final digit. Depth equals the number of digits after r; ordinal equals that digit string interpreted in base three, with root ordinal zero. A nonroot branch_kind is determined by its final digit. No hashing, randomness, allocation address or insertion-dependent identity is used.

5. Canonical expansion visits each frontier in ascending ordinal and constructs continuation, positive, negative children in that order. Ordinals are reassigned over the next frontier starting at zero. The output contains only the final frontier, matching generate_topology pseudocode. Parent identities and every ancestor are reconstructible from each explicit path even when those ancestors are not output members. visited_node_count counts actual node constructions and equals the sum of 3**k for k=0..depth on success.

6. AxiomSubject carries explicit declared facts: relation_count, raw_measure, compressed_measure, scale_count, erasure_cost, self_reference_capable and self_model_available. Counts and measurement ticks are exact integers from 0 through 9,223,372,036,854,775,807. Booleans are exact booleans. There is no numeric coercion, floating point, NaN, infinity, implicit unit conversion or negative quantity. Measures have exact units STRUCTURE_TICK or ERASURE_TICK and ticks_per_unit from 1 through 1,000,000,000. Raw and compressed measures require STRUCTURE_TICK and identical ticks_per_unit; erasure cost requires ERASURE_TICK. Ticks are abstract declared units, not authenticated physical energy or an inferred cosmological measurement.

7. Subject provenance is explicitly DECLARED_REFERENCE_INPUT, with a bounded source reference, method identity/revision and the actual originating diagnosis reference. Subject.state equals the verified parsed origin state. The subject's reference is an explicit input identity. The owner does not invent a subject from bits, topology nodes, role labels, file sizes, compression libraries or ambient world state. A later build_axiom_subject policy is a separate adoption.

8. Every complete axiom request evaluates all five checks in A1..A5 order, without short-circuiting after false: relation_count>0; compressed ticks<raw ticks; scale_count>1; erasure ticks>0; both self-reference facts true. The conjunction is computed after the fifth check. Each check immediately constructs its own immutable explained diagnostic before the next check. Every pass and failure is retained. The fifth record also cites the conjunction rule and carries overall_pass; no sixth record is added.

9. Source DiagnosticKind values TOPOLOGY and AXIOM use PROCESSING stage under YWE-REQ-0045 source compatibility and YWE-REQ-0048 producer diagnostics. Existing TEN fields, old rule meanings, old kinds and old stage meanings are preserved; matching canonical source/taxonomy/compatibility adoption precedes dependent implementation. Every PROCESSING envelope retains the actual verified origin DETECTION subject_reference and chain root. The first parent is that actual detection and later parents are previously produced records. Request, topology and declared axiom subject IDs remain distinct typed payload facts; no identity equality or subject-transfer waiver is inferred. Severity is the maximum of ancestor severity and current component impact. A true component has current impact INFO; a false component has current impact WARNING. For A1 through A4, disposition is RESOLVED iff that component passes, otherwise BLOCKED. The fifth record retains the independent factual A5 component result and evaluates the conjunction: its disposition is RESOLVED iff overall_pass is true, otherwise BLOCKED. Thus A5 may pass while its fifth envelope is BLOCKED by an earlier false component. This does not claim resolution of a prior state fault.

10. Topology produces one complete summary diagnostic on success or one rejection diagnostic when its verified origin can support a canonical chain. Axiom semantic admission refusal produces one input diagnostic and no component evaluations. A VERIFIED malformed-input or unavailable-profile diagnosis may support an explained rejection, with no fabricated AshState or measurements. Rejected origin validation, colliding references or unavailable validation cannot seed a fabricated root; the result carries exact rejection evidence and a typed PendingGenerationDiagnostic with empty produced_diagnostics.

11. Pure record production and persisted capture are distinct. Returned produced_diagnostics are immediate immutable semantic production, not collector acknowledgments, durable audit, authenticated input, physical measurement or completed producer coverage. The YWE-REQ-0045 source amendment defines that pure emission seam explicitly. Composition may subsequently authenticate an existing same-collector origin and persist each record in order under the YWE-REQ-0048 semantic capture contract, with truthful separate receipts. No effectful collector callback enters the pure owners.

12. All values use exact owned types, immutable copied tuples and fresh closed wire records. References have explicit ASCII grammar and bounds. Each complete business request/result has a 1,048,576-byte compact ensure_ascii JSON ceiling, checked before any serialization is returned; overflow refuses with GENERATION_RAW_BYTE_LIMIT and never truncates source evidence, nodes or diagnostics. Reflected corrupt values, cycles, unknown children and hostile primitive subclasses fail at the owned boundary without repr, conversion, equality hooks or exception-text capture.

13. Standalone pure computation does not grant ordinary session generation permission. Existing N3 actions and baseline eligibility are unchanged. Any future live generation composition requires its own current-snapshot, terminal/containment, source, lease, resource and capture admission. No current session is published by this slice.

14. Existing legacy identity/XOR/planner helpers and downstream A1-A6 pressure/exchange schemas remain unchanged. This policy supplies no role assignment, naming policy, subject-construction algorithm, complete GenerationPlanner, ArtifactEmitter, native runtime, M3 acceptance or release authorization.
