# M3 reference recovery safety policy

Policy identity: YWE-RECOVERY-SAFETY-001
Policy version: 1.0.0
Status: active N2 policy, adopted October 4, 2026 before dependent implementation.
Owner and partition: ywe_core. Requirement: [YWE-REQ-0041]. Decision: ADR-0031.
Implementation and M3 acceptance remain incomplete.

This local policy resolves concrete source tensions for the bounded immutable-value N2 reference slice. It does not add a canonical state class, RecoveryOutcome, DiagnosticKind, ContainmentTrigger, codeword or production fallback entry.

1. The specific canonical Fallback-Policy Registry entry action TRY_NEXT or ESCALATE_TO_CONTAINMENT controls candidate validation failure; the generic recovery algorithm's first-candidate immediate-containment pseudocode does not override that entry decision. The exact registry structure, applicability conjunction, known-good canonical target, rank/policy ordering and full STABLE postcheck are retained.
2. A pure verified original CORRECTABLE assessment whose APPLY_CORRECTION attempt is BLOCKED or RECOVERY_FAILED may invoke a separately named YWE after-correction-failure route. A completed normalization action with full actual non-STABLE/wrong-target postassessment and RECOVERY_FAILED may invoke a separately named after-normalization-failure route, retaining actual UNSTABLE. BLOCKED normalization is excluded and still requests direct containment. Each route retains its actual original class and exact failed-action decision reference. The canonical direct get_candidates interface remains DEGRADED-only. The YWE route uses the same registry entries, conditions, deterministic order and mandatory validation, and never invents a DEGRADED assessment.
3. A verified UNSTABLE assessment whose NORMALIZE_STATE path cannot be computed produces a policy request to enter containment. The actual canonical trigger at later entry is OPERATOR_REQUEST because the containment source explicitly groups operator/policy requests under that enum. The request carries request_origin=POLICY, this exact policy binding and reason NORMALIZATION_PATH_NOT_COMPUTABLE. No human request or completed recovery-validation failure is claimed. In the current closed reference algebra coherent UNSTABLE always has nonempty T and a ready N1 proof; the abstract mathematical no-path branch is unreachable. The supported local operational boundary is explicitly typed normalization-resolution UNAVAILABLE, retained as that observation and mapped by this policy to blocked-normalization containment. None/throw/malformed proof is a collaborator failure, not a claim that no mathematical path exists.
4. Applying a correction, normalization or fallback requires explicit SAFE propagation evidence bound to this operation and origin. RISK or UNAVAILABLE requests containment before the first value step. The policy request for missing propagation evidence uses request_origin=POLICY and this binding; RISK may use the canonical PROPAGATION_RISK trigger. No safety is inferred from absent policy, distance, bit count or a default boolean.
5. Every candidate's actual complete postassessment is produced by StateModel.assess with explicit current-owner SystemContext and freshly subject/profile/source-bound ClassificationEvidence. VALID alone is insufficient. STABLE is required for recovered-value certification. A CONTAINED or SAFE_HALT postcontext stops attempts even if that entry normally says TRY_NEXT; the existing lifecycle boundary is retained rather than cleared. Candidate extra-predicate FALSE with a STABLE assessment is an ordinary validation failure and follows the entry action. Unknown/failed predicate or capture is a retained evidence failure, never silently converted to FALSE or a later successful selection.
6. Per-codeword/predicate computation emits immediate ACTION_VALUE_COMPUTED step evidence under the canonical TEN envelope. A completed normalization, correction, candidate attempt or fallback summary emits OPERATION_DECISION with its exact canonical nine-field RecoveryDiagnostic and whole acknowledged step/postassessment references before any subsequent candidate. No new PENDING canonical RecoveryOutcome is introduced and no provisional RECOVERED certifies the operation.
7. N2 returns a typed mode/authority handoff; it does not enter containment, contact an authority, enter safe halt or commit a recovered value to a live session. A failed class is not a halted class. The required next N3 mode owner must admit effects before they occur, execute the directed mode transition, preserve monotonicity and terminal finality, and produce canonical containment/halt diagnostics from actual entry truth. Receipts for diagnostic capture cannot substitute for those effects.
8. Main recovery envelopes never decrease stage/severity. A postassessment is a distinct StateModel DETECTION/CLASSIFICATION child chain linked by explicit operation/action/origin metadata outside the TEN envelope. Each child record is acknowledged immediately; a child capture failure prevents recovered-value certification. An observed existing SAFE_HALT boundary receives only a separate denied-attempt audit, never an appended recovery event or transition on its frozen chain.
