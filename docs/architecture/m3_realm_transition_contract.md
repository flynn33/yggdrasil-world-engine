# M3 strict RealmEncoder / TransitionRegistry reference contract [YWE-REQ-0046]

[YWE-REQ-0046] Strict RealmEncoder and TransitionRegistry MUST use shared StateModel-owned, class-dispatched pure validation of complete source/profile/diagnosis evidence. They MUST require a valid parsed origin, preserve lossless full-state identity, evaluate declared applicability before full-vector XOR, and retain actual target validity without hidden normalization or fabricated assessment/TEN. Resolution MUST retain false availability. Exact immutable catalog, owner issuance and aggregate raw bounds MUST be revalidated; resulting candidates MUST NOT publish live state or redefine legacy algebraic helpers.

Status: Active contract. Governing decision: ADR-0037. This contract adds the strict realm/transition modules and shared StateModel diagnosis validation under YWE-REQ-0046. Canonical source migration is governed by YWE-REQ-0045 / ADR-0036; six-producer capture is governed by YWE-REQ-0048 / ADR-0039. These contracts precede dependent implementation. Runtime, schema, native and capacity acceptance require actual separate verification. The owner's full-roadmap direction covers continued development; the bounded N3 lifecycle contract does not define this slice.

## 1. Module behavior and boundaries

Add pure RealmEncoder, pure TransitionRegistry and a local RealmTransitionReferenceRunner for real Diagnostics composition. Outputs are immutable mathematical candidates, their constructed diagnostic prefixes and actual capture receipts. No normalization, SystemContext classification, recovery, session mode/generation publication, realm storage, WorldState commit, topology or artifact emission. N3 has no ordinary-transition action: that publication seam is a separate future adoption.

Source authority: canonical RealmEncoder and TransitionRegistry contracts; full-vector realm identity/transition/codeword transformation pseudos; exact C16 enumeration. They require valid source states, lossless full-state identity, ordered transition definitions, applicability before transformation, simultaneous x XOR c, deterministic well-formed output and explained failure. They do not promise that every computed target is profile-VALID.

Observed current implementation: ash_canonical.py's identity/transform/snapshot/planner helpers intentionally cover all512 represented states. StateModel.diagnose creates one actual STATE_VALIDITY/DETECTION TEN. Diagnostics.complete_assessment accepts StateDiagnosis and authenticates the full result against the captured prefix. StateModel.inspect_state is pure and emits nothing. At the observed a345 runtime checkpoint there was no strict RealmEncoder/TransitionRegistry class or StateModel.validate_diagnosis port. This contract defines the latter as a shared prerequisite used by topology/axiom.

Actual current WRW9 x C16 probe:9VALID targets,135TRANSFORMATION_COMPATIBLE targets. Each target is well formed. A strict result must retain that actual target diagnosis; do not secretly normalize or require post-VALID. The next strict operation revalidates its current source and may refuse a TC intermediate candidate. Strict generation destination encoding may therefore legitimately refuse it. Raw algebraic involution remains true across all512 x16; operational double application may refuse at an inadmissible intermediate state. This contract defines one strict operation from a supplied actual StateDiagnosis. A later planner that keeps one source root while changing intermediate candidates will need an explicitly adopted current-state/chain relation; no fake intermediate StateDiagnosis or ACK may close that seam.
