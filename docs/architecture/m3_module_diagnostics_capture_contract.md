# M3 module Diagnostics capture contract

[YWE-REQ-0048] Reference Diagnostics MUST validate the exact registered producer and complete current bindings and authenticate the first-completed same-collector origin before module admission. Pure captures MUST additionally authenticate class-validated issued results. Whole reservation and safe projection MUST precede acknowledgment; pure per-action production MUST remain separate from ordered persistence. Every admitted scope MUST finish once and expose actual first completion through distinct final observation without rewriting pure results or tentative nodes. Refusal, prefix, interrupted and persistence-failure evidence MUST retain actual truth, protected aliases and combined raw bounds. Existing collector limits MUST remain unchanged; producer kind recognition MUST NOT admit missing planner/emitter business policies.

## Concrete additive collector seam

The acyclic public assembly order is collector, StateModel, pure module owner,
then Diagnostics.register_module_producer(exact_owned_producer). Registration is
once-only in six fixed closed producer slots, before any module operation. It
returns ModuleProducerRegistrationReceipt(producer, status, failure_code) and
performs no clock, store, alias or canonical diagnostic effect. Exact supported
class, private self-issued owner identity, complete current source/profile and
adopted policy values are validated by trusted closed type helpers; no arbitrary
owner hooks or user callbacks run. Duplicate, foreign, changed binding and missing
business-policy owners refuse. The collector retains exact instance and immutable
binding fingerprint; every module_capture revalidates the same instance and full
bindings before IO. There is no unbounded registry, replace/unregister setter,
serialized capability or callback cycle. Registration acknowledges composition;
actual operation origin and issued result authentication remain separate checks.
Future planner/emitter slots refuse until their exact owned types and complete
business policies are adopted. Release has the same explicit assembly protocol.
Each supported producer supplies public API-only configuration() and
validate_owned_result(result)->bool. The collector uses exact supported class
dispatch outside IO, never instance overrides or central peer private helpers.
configuration returns the exact immutable full module binding; the producer alone
validates its own private cookie/issuer/result self identity and deep current
semantic graph. Exact boolean false refuses, and true is accepted only from this
trusted class dispatch alongside the independently authenticated actual capture
origin. Caller booleans and copied results confer no ownership. These two seams
add no wire node/alias/event and maintain fixed bounded assembly.

Proposed Diagnostics.module_capture(producer, context, *, execution_gate=None)
returns a ModuleCaptureAdmission with actual scope or null, exact operation ref,
status and failure. Producer is the exact configured module owner, not a string
chosen by the caller. Context carries the exact operation reference, current
full source/profile, actual origin, and owned dependencies. Pure contexts carry
their actual produced result; emitter context instead carries a prepared complete
plan and target, so admission precedes its first effect. The scope exposes
append(record), finish(owned_result) and
observe_final(owned_result, actual_first_finish_response). These are new ports,
not an existing unused N3 lane. The protocol can first implement only realm and
transition while the schema admits the future closed producer set. The reference
adapter authenticates actual origin in its private issued-scope ledger without
calling module hooks under collector IO. Missing actual origin refuses before
clock/store/alias effects; pure semantics can still be returned API-only.

All whole reservations are actual before admitted scope effect. Pure result
capture persists the already-produced tuple in exact order after computation;
final application result retains the actual append receipts and first finish.
An issued scope is retained and finishes exactly once even when a post-IO gate
check observes cancellation or the admission receipt itself is unconfirmed.
Exact copied/foreign scopes never gain ownership by matching reference text.
Capture's private issued gate identity must match this collector and session.
Standalone None path preserves old behavior and old serialized shapes.

Scope.finish writes the tentative PRODUCER_OPERATION sidecar/completion once;
its completion_observation_reference is null and is never changed. observe_final
writes the distinct PRODUCER_FINAL_OBSERVATION referencing actual first finish.
It writes
the immutable final first-finish observation once, outside the protected TEN
chain. Later storage/pin failure cannot rewrite its result or original response.
The returned ModuleCaptureReceipt separately exposes actual final_observation
after observe_final, alongside the unchanged first completion. The combined raw
guard includes both responses; the protected sidecar does not embed its own later
storage receipt or rewrite the immutable pure result.
Unconfirmed support/events remain distinct, charged and eligible for complete
closure pinning and paired export. Pins protect confirmed and uncertain members;
purge must resolve both dictionaries and never silently orphan a selected member.
No evolving history rewrite or recursively self-confirming sidecar is introduced.

For the effectful emitter, admission+required dispatch acknowledgment precede each
external action. Actual target effects occur outside collector/lifecycle locks.
The receipt step records actual success/failure/unknown effects and output hashes.
Capture failure after an effect preserves actual effect truth and blocks later
dispatch. Ordinary refusal cannot claim rollback. Release uses the same semantic
records and closed bounded safe fields without expensive discarded payload work.

Existing trusted collector code enters no producer callback under its IO lock.
Injected clock/store may reenter lifecycle; gated terminal/cleanup controls use
