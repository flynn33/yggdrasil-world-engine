# Core operation permit and normalization integration

Status: ADOPTED_REFERENCE_API. [YWE-REQ-0051] Decision ADR-0043. These API declarations do not assert current runtime implementation. Dependent implementation follows owner adoption and issuance. The standalone Core operation permission does not authorize RecoveryEngine authority predicates, Session publication, or revival of a revoked SessionExecutionGate.

CoreModuleLifecycle.admit receives an immutable bounded operation_bindings tuple of exact (scope_ref, allowed_stages) pairs computed by the class-owned orchestration route. CoreModuleLifecycle.execution_gate requires the exact original admitted ModuleTicket in that owner's bounded ledger, the configured collector/source/profile, and current generation. A copied ticket, a value-equal capability, a foreign collector or a corrupt identity refuses before methods or hooks. Public construction never issues authority.

CoreExecutionGate.configuration returns an exact immutable tuple (collector, operation_reference, source_binding, profile_binding, generation). CoreExecutionGate.validate_issued_for_collector checks its own original factory/cookie/self identity and exact immutable collector/scope metadata without entering the owner or calling I/O. CoreExecutionGate.for_operation(original_gate, actual_scope_reference, allowed_stage) validates the original ticket/current generation and the exact registered pair, then privately issues a child gate. Child gates share the original ticket and cancellation authority, cannot issue further children, and cannot widen their stage group. At most64 children are issued per ticket. No prefix match confers permission. The actual closed run suffixes are :source, :chain, :normalized, :final, :destination, :topology, :axioms and :planner; a preexisting diagnosis and requested normalization context retain their actual references. A separate emission command retains its exact operation reference for all dispatches.

CoreStageGrant retains operation_reference, finite stage, generation, uint64 grant_sequence and status GRANTED/CANCELLED/UNAVAILABLE. stage_grant uses a short owner lock outside collector I/O, checks the exact current ticket/gate/phase, and grants one declared bounded stage. All20 stage names are closed in the API inventory. The maximum is64 grants per admitted ticket; a larger requested grammar refuses typed preflight before effects. No callback, clock, storage or peer call runs under the owner lock. One grant permits trying the stage; it does not claim completion or an evidence ACK.

Core stop first latches closed/STOPPING and the generation cutover, then seals every ordinary issued gate before cleanup. It does not wait for a blocked clock, store, normalization or capture callback. capture_disposition reads a separate tiny token lock nonblockingly, without lifecycle lock or callback. The trusted sealed latch is set before attempting token synchronization: a busy read returns UNAVAILABLE and no later read returns ACTIVE after cutover. An already entered callback may physically finish; its actual value/effect stays interrupted or uncertain audit and cannot grant the following ordinary stage or publication. Disposition reads, append rechecks, first-finish cleanup, final observation and return audit mint zero stage grants.

Requested normalization is explicit CoreNormalizationRequest(NormalizationPlan, NormalizationContext). The actual plan original diagnosis must equal the submitted Core origin structurally and remain authenticated under the complete current source/profile/normalization policy. The Core route calls StateModel.validate_normalization_plan through its class-owned implementation; only VALIDATED/PLAN_READY enters actual value apply. TC without a requested plan refuses, with no implicit healing. The existing normalization helper/lambda dispatch must also use StateModel's class-owned implementation rather than an injected instance override. No target-selection or normalization mathematics changes.

StateModel.apply_normalization and the exact _NormalizationOperations.apply implementation gain optional execution_gate:CoreExecutionGate|None=None. Existing None behavior remains unchanged. Diagnostics.normalization_capture accepts that same gate; assessment_capture and module_capture accept only the enumerated exact Session/Core classes in their separate authority branches. Diagnostics.complete_normalization accepts the exact Core gate for once cleanup of the actual result/first completion. Required Core grants bracket actual computation and post-validation; collector admission and every ordinary append check the immutable token before and after callback I/O. No collector lock calls stage_grant or a producer callback. Busy/reentrant gated support/finish admission refuses promptly without inventing ACKs. A Session gate at a Core-only entry and a Core gate at Session/Recovery publication refuse before hooks.

Core retains the original TC diagnosis, full actual NormalizationResult|NormalizationFailure|NormalizationCaptureFailure and its actual first DiagnosticsCompletionReceipt separately. Only actual NORMALIZED success plus COMPLETE confirmed first completion and a current permit authorizes one fresh normalized StateModel diagnosis and first completion. That actual fresh VALID root becomes the runner's initial origin; the original diagnosis/root is never relabeled. Failure, incomplete capture or a lost finish response retains the actual prefix and known/unknown observations, then refuses generation. Genuine late granted results may be retained through cleanup, but no following ordinary post-capture, planner or dispatch stage is entered.

The whole-pipeline proof includes original diagnosis root/event/support, actual two-record normalization scope and plan/validation/step/result support, first completion, fresh normalized diagnosis/completion and all generation roots/scopes/pages/action leases. The fresh normalized diagnosis is also the pipeline initial origin and is charged once. Global1024-event/6144-alias/32MiB-main/2MiB-support/32-incident/8-active-scope caps remain fixed. The Core packet cap and grant limits do not expand collector capacity or borrow N3 reservations. The exact source4 policy/constructor/host mapping and independently reviewed whole-pipeline proof precede dependent implementation.

Required tests cover unissued/copy/foreign collector/source/profile refusal before hooks; both authority substitution directions; held-token UNAVAILABLE then SEALED; Event-controlled stop during blocked clock/support/event/normalization/capture; no next ordinary stage after actual late completion; unknown commit bytes preserved without ACK; immutable first-finish/later-observer truth; raw-cap refusal before a following stage; and the nontrivial H4 TC-to-normalization-to-four-step-chain-to-eight-document pipeline under the fixed global limits. These are implementation obligations, not executed Core test claims.


The implementation MUST enforce all exact issuance/current-scope/token, class-owned dispatch, normalization, authority-substitution, cancellation and once-cleanup rules specified in this companion and its API rows. Collector I/O MUST NOT invoke owner grants or producer callbacks. Every accepted ordinary stage MUST retain its actual prefix and independent pre/post token checks; stop MUST seal admission before callbacks and MUST NOT wait for a blocked external callback.
