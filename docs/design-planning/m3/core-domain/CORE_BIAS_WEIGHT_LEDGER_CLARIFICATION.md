# Core bias weight ledger clarification

Status: PROPOSED_SCOPED_IMPLEMENTATION_CLARIFICATION; no runtime claim. Requirement YWE-REQ-0051 / ADR-0043. The unchanged53 wire definitions,44 owner ports and compiled Core policy bytes remain controlling. This companion makes the operational mapping and replay semantics explicit; it does not change authored format acceptance.

`DeterministicPolicy.merge_bias(before, terms, *, logical_epoch, retention_q6)` takes an exact BiasState and an immutable tuple of exact BiasEvent bodies. It MUST NOT infer event provenance from raw BiasTerm inputs. Every event retains its actual unique(domain,target) terms and evidence. [YWE-REQ-0051]

For an operational before state, derive the sorted unique ASCII tuple of(domain,target) keys from all retained before.events. Its weights MUST contain exactly one row per key, including zero weights, with option IDs bias:00 through bias:63 matching that existing sorted rank. Empty event ledger requires empty weights. Missing, extra, duplicate or noncanonical rank mapping MUST produce a truthful REFUSED/CORE_PROVENANCE_MISSING at weights before a proposed update; the original before graph remains evidence. These semantic restrictions do not invalidate structurally legal authored wire specimens. [YWE-REQ-0051]

Validate the explicit nondecreasing epoch and retention0..Q6. Decay each existing mapped current weight by floor(weight*retention_q6/Q6) once per elapsed logical step, maximum1024. Retained ledger contributions MUST NOT be added again after decay. Equal event IDs require exact complete equal event bodies; equal replay adds zero new contribution, while unequal bodies refuse CORE_FACT_CONFLICT. Repeated identical new event IDs are deduplicated before summation, without losing the declared source body. [YWE-REQ-0051]

Derive the new sorted key union after admitting genuinely new event bodies. Add only their signed contributions per exact key to its decayed existing current weight (or zero for a new key). Clamp once to0..Q6 after all new signed contributions, never once per term. Output weights MUST use new sorted ranks, so insertion can rename old output ranks while its retained exact pair ledger preserves association. A rank is a state-local encoding, not a persistent pair identity; callers MUST NOT transfer ranks between different ledgers. This avoids delimiter ambiguity and digest collisions when IDs themselves contain colons. [YWE-REQ-0051]

The complete proposed ledger MUST preserve all old and genuinely new events in ASCII event-ID order. No zero key or old event is silently evicted. More than64 distinct keys or512 events refuses CORE_RESOURCE_LIMIT before producing an update, with the actual before/input prefix retained. Raw whole-Core1MiB remains independent and may refuse a legal Cartesian-maximum shape. The result effect remains PROPOSED_ONLY; no M4 memory or accepted-world commit is implied. [YWE-REQ-0051]

The independent controls below cover insertion-rank remapping, delimiter ambiguity, duplicate replay after decay, exact-body conflict, all-new single clamp, explicit epochs and finite capacities. Their expected values are authored arithmetic, not actual production execution. Under the declared per-key one-term/event and512-event limit, an admitted pre-clamp key sum is bounded by513,000,000 absolute ticks, well within signed63. Unrepresentable primitive/counter inputs still refuse at their owning boundary; do not fabricate a reachable arithmetic-overflow witness inside that bounded domain.
