# Source4 normalization stopped-post capture prefix

Status: PROPOSED_NARROW_API_CLARIFICATION_NOT_RUNTIME_ACCEPTANCE. Requirement YWE-REQ-0051 / ADR-0043. This correction preserves the exact NormalizationCaptureFailure class and every existing wire field, old three source families, policy bytes, rule IDs and normalization mathematics.

The M3_GENERATION source-family NormalizationCaptureFailure MAY carry attempted_diagnostic=null only when all of the following facts hold together: origin_validation_status=VERIFIED, plan_validation.validation_status=VALIDATED, plan.decision in ALREADY_VALID or PLAN_READY, exactly one actual confirmed emitted COMPUTATION record, zero post_validity_diagnostic, zero normalized_state, outcome=FAILURE, failure_kind=diagnostic_capture, failed_field=normalization_capture, capture_status=NOT_CONFIRMED and failure_code=DIAGNOSTIC_CAPTURE_UNCONFIRMED. The actual_state and exact existing zero-or-one NormalizationStep MUST remain unchanged from the confirmed computation; PLAN_READY requires its one step and ALREADY_VALID requires none. [YWE-REQ-0051]

The null value means that the following post-validation stage was not entered or no post-validation result exists; it is not an attempted or acknowledged canonical TEN. No actual POST_VALIDATION record, diagnostic or complete normalization success MAY be inferred. Historical source families MUST continue requiring the original nonnull attempted record and original constructor/serializer/schema behavior. A current null-attempt branch without the exact one-record prefix MUST refuse construction, revalidation and serialization. [YWE-REQ-0051]

After a Core cancellation, the owner MUST preserve the actual computed state/step and confirmed COMPUTATION prefix, return this current-family unconfirmed capture failure, then allow once cleanup against the exact original scope/result and actual first response. It MUST NOT execute the revoked post-validation kernel, append a following ordinary TEN, manufacture NORMALIZED, or replace the original diagnosis. Collector coverage remains incomplete/uncertain as actually observed; this packet supplies no new ACK or evidence root. [YWE-REQ-0051]

Unstopped actual normalization still returns its full two-record NORMALIZED packet. Constructor/schema negatives cover historical null, empty/two-record prefix, nonnull post/normalized result, REJECTED status, wrong code/field and PLAN_READY without its actual step.
