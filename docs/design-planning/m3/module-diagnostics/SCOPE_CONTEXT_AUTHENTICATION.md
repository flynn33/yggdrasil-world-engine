# Original module scope and expected context authentication

This API-only clarification belongs to the adopted module capture contract, [YWE-REQ-0048], with the effectful composition under [YWE-REQ-0049] and current Session use under [YWE-REQ-0050]. It changes no business wire type, raw field, reservation, global cap, semantic record or effect grant. It makes no runtime acceptance claim.

`ModuleCaptureScope.validate_issued_for_context(scope, collector, producer, context, *, execution_gate=None, emitter_control=None) -> bool` is a public exact-class method on the existing API-only scope. The caller uses class-owned dispatch outside collector IO and outside producer/lifecycle locks. It MUST return an exact bool without invoking owner callbacks, grants, clock, store, instance overrides, arbitrary serializers, coercion, metaclass equality/hash, or a blocking lock. [YWE-REQ-0048]

The method MUST authenticate the collector's own original scope issuance: exact scope/service/native classes, original self identity, exact live service and native ledger membership, native collector identity, expected exact collector, expected original registered producer identity, exact original context identity and complete saved original context wire fingerprint, native operation reference, expected exact execution gate identity, and expected exact emitter control identity. It validates the supplied exact context through owned public value validation before any value comparison. It reads only collector-owned metadata and invokes no peer-private helper or owner method. Foreign, copied, directly constructed, reflected, mismatched, mutated or unissued inputs MUST return false before IO. [YWE-REQ-0048]

The complete context fingerprint is computed from the already validated original six-field ModuleCaptureContext at actual scope issuance. The validator compares the current exact original context with that saved fingerprint; changing a valid nested field cannot transfer authority. A valid data copy of the context does not transfer the scope because the admitted original context identity is required. The producer and tokens remain the exact objects supplied at actual admission; string equality or matching source hashes alone do not authenticate them.

Authentication MUST remain readable after token seal, cancel, stop, emitter shutdown, completed scope finish, failed admission response or final observation so the caller can retain and clean up its actual scope once. A true result proves original association only; it does not grant eligibility, a stage, an append, an effect, a completion ACK or a new scope. Token disposition, actual first response and stage/capacity checks remain separately required. [YWE-REQ-0048]

Runner, emitter and current Session callers MUST authenticate the actual returned scope against their exact original producer/context/gate/control before retaining, appending, finishing, observing or auditing it. A genuine scope for that original context is retained for once-only cleanup even if the admission response is unconfirmed or its operation text/status is wrong. A genuine scope for another context or producer is left untouched; an exact class check alone is insufficient. No fabricated receipt replaces the actual first cleanup response. [YWE-REQ-0049] [YWE-REQ-0050]

Required controls include an actual admitted foreign same-collector scope that stays unfinished/unfailed and receives no append/finish/observer/audit when injected into another admission; actual original scope with a wrong admission operation/status that still receives its one cleanup; copied/foreign collector/producer/context/gate/control; reflected original context mutation; hostile nested fields with zero equality/hash/coercion hooks; and authentication of the genuine original scope after seal and first finish. These controls allocate no new resource lane and do not broaden producer eligibility.
