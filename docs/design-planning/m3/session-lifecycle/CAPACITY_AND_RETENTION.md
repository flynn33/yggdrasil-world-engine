# N3 lifecycle capacity and retention allocation

Status: adopted N3 capacity contract, October 11, 2026; implementation and runtime acceptance remain outstanding. The observed implementation boundaries below refer to preparation source revision 0949184b7f1be0960fec9dd409cbf09647921e61. The frozen external proposal remains preserved. This repository package reconciles the adopted policy hash and business inventory and makes its representation controls portable; it claims no N3 runtime acceptance.

## Observed implementation boundaries

`core/ash_pattern_engine/diagnostics.py` is the current bounded owner. `_begin` checks retained plus outstanding reservations against 1024 events, 6144 permanent aliases, 33554432 serialized bytes, 32 incidents and 8 active scopes; its clock observation enforces 600000ms duration. `_supporting` separately enforces the 2097152 supporting-byte cap,32768B leaves and fixed per-kind quotas. Existing `_begin` has no separate support-byte reservation parameter; the proposed typed lifecycle lane must add authentic support reservation accounting without weakening the existing limits. A normal N2 `RECOVERY_ENGINE` scope reserves 768 events, 31588352 bytes, 5931 aliases and all 32 incidents. A genuine earlier retained incident or another one-incident scope prevents this reservation. `_complete` releases unused reservations; it does not erase retained incident truth or recycle `_aliases`. `purge_completed` is not an alias reset.

`_validate_chain` accepts StateModel assessment chains and the existing recovery/fallback producer domains. The recovery domain explicitly forbids CONTAINMENT and SAFE_HALT payloads. `_append` has no lifecycle producer branch. `RecoveryEngine.recover` already owns the first and only N2 scope finish. There is no existing public session registration, lifecycle capture, pin, freeze or once-final session result observation API. The ports below therefore require explicit contract/schema/source composition changes before implementation.

`diagnostics_values.DiagnosticEvent._coherent` allows ACTION_OBSERVED with null envelope and null diagnostic_reference. This provides a truthful control event shape for containment resolution. `state_values.canonical_source_baseline` recognizes a complete declared source vector; it does not authenticate host file bytes. Only the separately configured Diagnostics host mapping can provide old-domain verified source evidence.

Canonical `containment-safe-failure-semantics.pseudo.md` specifies four containment trigger mappings, five halt trigger mappings, containment as an ESCALATION after the triggering recovery/fallback, and halt as TERMINAL after containment or escalation. It imposes no four-record lifetime limit. An old CONTAINMENT/ESCALATION cannot receive a recovery-stage resolution successor or an ESCALATION successor with a disallowed containment parent. This contract preserves that immutable branch and links a new actual StateModel root through a typed resolution observation.

## Exact finite owner scope

One ReferenceSessionLifecycle is bound once to one RecoveryEngine identity and one session. ReferenceSession is an issued facade with read/execute/history delegation and no independent mutation authority. Legacy standalone recover with lifecycle_owner=None and execution_gate=None remains unchanged.

The owner admits at most two RECOVER attempts and sixteen mode commands: fifteen nonterminal containment/resolution attempts plus one reserved first halt. It retains at most eighteen ordinary command results, thirty-six confirmed and thirty-six attempted lifecycle projections, eighteen pending projections, sixteen resolution observations and two genuine N2 results. These are local finite admission limits, not canonical source limits. A separate denial lane retains at most sixteen terminal refusal observations. Later refusals preserve terminal truth and saturated fixed-size health counts without scanning caller bodies, allocating new aliases, extending history, or claiming an individual persisted audit record.

A full submitted expected snapshot is carried once in the primary request. Nested authority/boundary/cause values carry exact raw request and expected-snapshot reference scalars; these must match the validated primary request before COMPLETE_SPECIFIED_SAFE_GRAPH can be returned. At admission the caller's full expected snapshot must equal the actual public snapshot. The owner issues a distinct active snapshot with active_operation_reference and retains it in the lease. Commit compares actual full current state against this owner-issued active snapshot, not the earlier caller before-snapshot. Same state bits reached at another generation cannot restore lease authority.

The recognized policy fields include the exact adopted ID/version/path and compiled LF SHA256 in the safe binding node; policy recognition is not host verification. Snapshot mode is NORMAL, CONTAINED or SAFE_HALT. FAILED is an actual observed class, not a fourth mode. current_assessment_reference and observed_system_state_class become null at publication and remain null until a new actual current-context assessment and its complete-assessment response are accepted. Halt leaves both null. Mode truth never fabricates observed assessment class.

## New public capture and retention allocation

The exact business types are the frozen `BUSINESS_API_INVENTORY.bound-input.json`. The exact safe field/domain/key inventories are `SAFE_FIELDS_AND_LIMITS.json`. No free-form dict configuration, caller budget, supplied opaque handle, caller authentication boolean or arbitrary callback is an authority input.

Validate full recognized N3 source vector, paired recovery pins, actual complete profile and adopted policy binding. Registration/pinning hold zero N3 incident reservation before a genuine N2 scope. A failed registration still leaves an AUDIT_BLOCKED semantic session capable of an independently justified mandatory halt.
- Diagnostics.attach_result(handle, result: StateAssessment|RecoveryValuePacket, *, relation: SessionChildLink|None=None) -> receipt. Attach only actual owned complete same-collector prefixes and first completion observations. Do not reemit old records, reinterpret supplied references as ACKs, or relabel foreign data as authenticated.
- Diagnostics.lifecycle_capture(handle, *, execution_gate) -> SessionLifecycleCapture; retain the exact privately issued gate for pre/post IO checks and inherit it in post-mode children. begin(command, *, before, origin_refs, terminal=False) -> (scope|None, SessionLifecycleCaptureAdmission), with the exact fixed budgets below.
- SessionLifecycleScope.observe_clock() -> actual ClockObservation under nonblocking collector acquisition, IO-depth refusal and pre/post gate checks. Unavailable/busy/regressing time stays unavailable; no admitted scope means Pending rather than a fabricated canonical time.
- SessionLifecycleScope.append(record: LifecycleRecord) -> actual CaptureReceipt. Supports are immutably committed before event acknowledgement. Failed/unknown native outcomes remain real unknown-storage outcomes with fixed partial health/meta evidence.
- SessionLifecycleScope.assessment_capture(relation: SessionAssessmentLink) -> actual StateModel scoped capture sharing the parent's four event slots. complete_assessment is once-only per actual pair.
- SessionLifecycleScope.append_resolution(observation) -> CaptureReceipt. Produce SESSION_LIFECYCLE/ACTION_OBSERVED/CONTAINMENT_RESOLUTION_RECORDED with null TEN and null diagnostic_reference; attach exact SESSION_RESOLUTION evidence and actual context. Closed event outcomes map RESOLVED to COMPLETED, REFUSED to REJECTED, and UNCONFIRMED to NOT_CONFIRMED; the typed support preserves the original resolution status.
- SessionLifecycleScope.finish(tentative_result) -> first actual SessionLifecycleCompletion exactly once; own completion field is null in the tentative result. No session layer refinish of a completed N2 recovery scope.
- Diagnostics.observe_session_result(handle, final_result, *, actual_result=None) -> once-final SessionRetentionReceipt. A compact raw-limit descriptor may supply its actual immutable result through the typed API-only sidecar. Commit one final SafeSessionCommandEvidence containing the first actual finish response, never rewrite an earlier immutable tentative key. The observer's own returned retention receipt stays in a private bounded API sidecar outside the protected graph, so it cannot recursively confirm itself.
- Diagnostics.pin_history(handle, history) -> exact graph-closure receipt; Diagnostics.freeze_terminal(handle, history, actual_terminal_publication) -> terminal closure receipt. Freeze accepts actual owner publication, closes ordinary session gates in memory and pins exact admitted event/support keys. At cutover, exact bounded pending halt bridge/terminal/completion slots and references are predetermined. No new or later main-chain successor is allowed; an issued private terminal capture permit may fill only those already declared pending slots and their once-only completion. Ordinary gates remain SEALED. No pending slot is an ACK or emitted canonical record until actual construction/capture succeeds.
- Diagnostics.denial_capture(handle, frozen_snapshot, *, denial_ordinal=1..16) -> separate issued scope. append(actual denial DiagnosticEmission) and finish(tentative denial) are once-only. Diagnostics.observe_session_denial(handle, final_denial) -> once-final sidecar receipt preserves the actual first finish response through bounded final denial support, with no extra event or main-chain extension.

pin_history pins the actual current immutable member closure through a private issued selector ledger without an evolving SESSION_HISTORY node/event. Current-member completeness is not a final terminal-index claim. The owner in-memory cutover seals before IO. freeze_terminal writes the single immutable SESSION_HISTORY and at most forty pages once after the terminal finish and once-final observation, using actual sealed main history including the terminal result/completion. Later denials and interrupted cleanup remain separate audit roots and never rewrite or extend that final main index. Missing/unknown members make coverage partial.

The lifecycle admission owns a bounded closing reservation through the once-final observation. Event/incident and unused resources can be released as finalized, but bytes/support/aliases needed by the closing observation remain reserved until its single accepted observation, typed rejection or expiry. It is not legal to release all capacity and then append final supports without fresh authentic admission. One final support node per command/denial is counted below. No immutable support key is overwritten to append a later receipt. Session sidecar/index ownership is checked by issued identity; no equality copy can create issuance authority.

No automatic purge, rotation, unpin, alias reset or cap increase is used to make this fit. Existing CapturePurgeRequest max1928 and old-kind quotas stay unchanged; pinned session roots cannot be passed through the old purge API. A future explicit session-release/purge API requires its own adoption and is outside this finite session scope.

## Decision and chain order

RECOVER creates a fresh captured child StateModel origin, with deterministic request_ref + ':origin:assessment' and actual NORMAL context. Submitted propagation and external-authority evidence must already bind that fresh origin; no silent rebind or copied predicate facts are allowed. The fresh pair completes before the authentic N2 reservation. N2 then finishes exactly once through existing engine ownership. Only afterward does N3 seek its actual lifecycle admission. A second full N2 is not guaranteed: 768+768 exceeds 1024 events, held aliases214 plus5931 exceed6144, and even one retained incident plus32 exceeds32. Admission refusal is required when the actual collector says no.

A subsequent actual session handoff is represented by a zero-step RECOVERY bridge under the current main session CLASSIFICATION/RECOVERY root, then containment ESCALATION or halt TERMINAL. N2's own ESCALATION is not made the containment parent. RecoveryDiagnostic.steps is exactly () for every N3 bridge; this is a session decision observation, not a mathematical/provider step. Up to36 immutable old-domain RECOVERY_DIAGNOSTIC nodes are explicitly charged, subject to the unchanged64-kind quota.

Every successful nonterminal containment or resolution publication requires a new two-event actual post-mode StateModel assessment under the same four-slot lifecycle scope. Containment bridge + containment + pair uses four. Resolution control + pair uses three. Pure target validation emits zero events. The finite proof conservatively allows sixteen pairs even though only fifteen nonterminal mode commands can actually occur.

Direct resolution binds the exact current CONTAINED snapshot/containment record, current full source/profile, explicit authorized operator/policy request, SAFE propagation and SATISFIED CONTAINMENT_CLEAR. StateModel.validate_resolution_target is pure, with prospective context(false,false), full target diagnostic and expected STABLE/NO_ACTION only when verified. It does not enter NORMAL, reuse old N2 provenance as current proof, or emit a fake classification. Under the owner lock recheck all bindings/evidence/active lease, then atomically replace target, enter NORMAL and increment generation. Freeze the old contained chain and create the required new actual assessment root. A captured typed resolution observation links old containment and new root. Refused attempts preserve current mode/state/generation; committed state followed by failed postassessment/capture remains COMMITTED/effects=true with AUDIT_BLOCKED and genuine incomplete evidence.

Halt requires an actually satisfied one of the five canonical trigger guards. In particular, CONTAINMENT_BREACH requires actual CONTAINED state and explicit satisfied breach evidence; merely selecting escalation route is insufficient. UNAVAILABLE authority is not UNREACHABLE. Once a justified mandatory halt is decided, latch mode SAFE_HALT, terminal flag, generation and close the private ordinary execution gates before clock/storage/provider IO. Missing registration, capacity, UTC/monotonic time, canonical predecessor or original assessment must not undo the latch. They produce a truthful PendingLifecycleRecord and partial/uncertain health, not fabricated canonical fields or ACKs. The reserved terminal generation is the final uint64 value; ordinary publications leave it available and never wrap.

A first terminal SessionTerminalChainClosure references the request, optional actual bridge, same outer terminal reference/TEN and actual terminal publication. It contributes one typed supporting node and no extra TEN/event. The halt full diagnostic chain contains complete prior grouped immutable entries at max21, excludes the current halt result and uses the typed nonrecursive terminal emission/closure to avoid self-reference. If the canonical payload cannot be constructed, closure must preserve that absence rather than invent a terminal emission.

Stage grants are private API-only bounded records (at most8192 per recovery), not new persisted events/aliases. Checks happen under the lifecycle lock before each further stage, the callback runs outside that lock, then bindings are rechecked. Already-granted callbacks cannot be physically preempted. Mandatory halt closes gates before later IO; an in-flight older result is finalized through its once-only cleanup/late-audit lane, without adding a new frozen main-chain successor or later publication. Filling the predetermined halt slots is the narrowly authorized terminal capture lane, not an ordinary post-seal successor. Trusted collector code never enters the lifecycle owner lock or invokes a lifecycle execution callback. Injected clock/store ports may synchronously reenter the owner under the existing collector RLock; the new lifecycle admission/finish/pin/freeze/observer paths therefore refuse nonblockingly while IO is active, instead of recursively waiting or extending a frozen chain. Existing standalone Diagnostics invokes its explicitly injected clock/store ports under its collector lock; that behavior is observed and unchanged. Session terminal sealing must have a short nonblocking in-memory cutover path independent of that IO lock. Native clock/store calls can remain in flight; their eventual outcomes are retained as late/unknown evidence and rechecked before any further gate or publication, never represented as physically preempted.

## Serialized raw business guard

A safe-graph bound does not establish the raw32MiB business bound. `recovery_values._Record.to_record` recursively copies nested records and tuples; SessionOperationResult and SessionHistory repeat a genuine N2 packet, while a halt grouped full chain repeats prior results again. Measuring each member below32MiB is insufficient. The executed synthetic controls show one33553422B member fitting, a two-copy history67106930B refusing, and a four-copy terminal envelope134213846B refusing. These are JSON arithmetic controls, not canonical N2 witnesses.

Before an ordinary state/mode CAS, the serialization owner must measure (1) the complete prospective result including actual known N2 evidence and bounded future completion fields, (2) the prospective history after adding it, and (3) the anticipated first terminal canonical closure/history with every permitted raw repetition. Use the exact sort_keys=True/separators=(',',':')/ensure_ascii=True/allow_nan=False encoding and a closed registered serializer for actual keys, headers and flattened profile records. Unknown future time/reason/receipt fields use a pure finite sizing plan with genuine maximum domains, never fabricated observations. A512-character astral reason can occupy6146B including JSON quotes; UTF-8 length or six bytes per codepoint is not a valid ensure_ascii bound.

Do not first materialize an unbounded recursive to_record tree. Count an immutable acyclic object DAG with exact serializer adapters and repeated wire multiplicity; memoizing subtree size is valid only if every repeated wire occurrence is still added. Stop at cap+1 and return overflow without claiming an exact oversize length. Reject cycles, unsupported types and callbacks. All materializing business to_record/export serializers independently enforce33554432B, including refused/failed results and pure history/replay reads. The size guard applies before observation callbacks and before allocating materialized serialization copies, including repeated replay returns. Guarding only COMMITTED results is insufficient.

Overflow before ordinary CAS returns compact SessionRawBusinessFailure with SESSION_RAW_BUSINESS_LIMIT, phase, actual before/after/effects and a stable history reference; no raw N2 or diagnostic payload is embedded in the descriptor. The owner retains the actual complete immutable bounded object DAG, uses existing shared references and finite command/member limits, and serializes none of the oversized recursive wire copies. The safe final command node projects descriptor phase/coverage plus actual raw-limit failure. Repeated overflow adds no unbounded command/event/alias allocation.

Mandatory halt latches first even if this guard refuses its canonical raw payload. Preserve the entire actual API-only immutable trace, PendingLifecycleRecord(reason RAW_BUSINESS_LIMIT), actual terminal truth and truthful PARTIAL persisted coverage; the serializer refuses, never truncates. A whole API-only memory trace alone does not meet canonical postmortem access without memory or prove a full protected persisted graph. COMPLETE_SPECIFIED_SAFE_GRAPH means only the precisely declared safe projection, which explicitly omits raw business packets and free notes; it is not full canonical raw-payload persistence.
