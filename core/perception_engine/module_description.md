# PerceptionEngine: M3 reference module contract

[YWE-REQ-0051] Decision ADR-0043. The normative behavior is defined in [the Core domain contract](../../docs/design-planning/m3/m3_core_domain_contract.md) and [its exact API inventory](../../docs/design-planning/m3/core-domain/CORE_API_INVENTORY.json).

PerceptionEngine produces immutable subject/scope views of a declared truth input. Conflicts use exact scope, subject, fact identity and tier. Rules reveal, hide or emphasize existing entities/facts and attach derived tags while retaining all evaluated observations.

The exact class-owned public operations are configuration, compose_overlay and validate_owned_result. Constructors validate immutable configuration/dependencies without hooks or activation. New records use the closed m3_core_domain_schema.json. Existing M2 engine-interface/metadata schemas and accepted fixture bodies remain backward compatible authored formats; wire validation does not confer runtime issuance or committed-world proof.

Unknown references and contradictory equal-tier facts refuse. Visible and hidden entity sets form the exact input partition, and the input truth hash remains unchanged. The owner cannot rewrite objective geography, higher truth, or another subject's scope. Whole Core packets are limited to1MiB, CoreDiagnostic to8,192bytes and operation diagnostics to32. Domain-specific array maxima remain subject to whole-packet preflight. Refusal retains the actual evaluated prefix; no silent healing, clipping or fabricated ACK occurs. Integer q6 arithmetic, ASCII ties, explicit seeds/logical epochs and fresh compact serialization are fixed by the central policy.

The platform-neutral CoreModuleLifecycle binds an exact configured owner. It limits each operation to64 grants/children,8 simultaneous tickets and64 lifetime ledger entries. Stop latches before cleanup or callbacks; an actually granted late outcome remains interrupted audit and cannot authorize the following ordinary stage. Forsetti owns later host discovery, entitlement and activation. Optional profile names, symbols and content cannot rewrite ASH or Core truth.

This contract finalizes the M3 interface; it does not claim runtime acceptance. Acceptance requires the complete28-invariant/five-category executable judgment, per-module failure/no-op/resource proofs and clean unfiltered validation. M4 persistent world/branch/player acceptance and M5 content activation remain separately owned roadmap work.
