# AshCoreFacade: M3 reference schema and interface contract

[YWE-REQ-0051] Decision ADR-0043. The normative behavior is defined in [the Core domain contract](../../docs/design-planning/m3/m3_core_domain_contract.md) and [its exact API inventory](../../docs/design-planning/m3/core-domain/CORE_API_INVENTORY.json).

AshCoreFacade projects bounded explicit profile rules over actual approved ASH generation results. A privately issued CorePlanPermit is required after complete plan capture. The snapshot preserves the original TC signature, optional actual normalization step, normalized source identity, actual destination identity and complete zero-to-five codeword trace.

The exact class-owned public operations are configuration, project_patterns and validate_owned_result. Constructors validate immutable configuration/dependencies without hooks or activation. New records use the closed m3_core_domain_schema.json. Existing M2 engine-interface/metadata schemas and accepted fixture bodies remain backward compatible authored formats; wire validation does not confer runtime issuance or committed-world proof.

It never invents an intermediate diagnosis, TEN, root or ACK. It preserves the exact source/profile and the complete evaluated membership observations. A copied immutable packet remains data and does not issue a permit. Whole Core packets are limited to1MiB, CoreDiagnostic to8,192bytes and operation diagnostics to32. Domain-specific array maxima remain subject to whole-packet preflight. Refusal retains the actual evaluated prefix; no silent healing, clipping or fabricated ACK occurs. Integer q6 arithmetic, ASCII ties, explicit seeds/logical epochs and fresh compact serialization are fixed by the central policy.

The platform-neutral CoreModuleLifecycle binds an exact configured owner. It limits each operation to64 grants/children,8 simultaneous tickets and64 lifetime ledger entries. Stop latches before cleanup or callbacks; an actually granted late outcome remains interrupted audit and cannot authorize the following ordinary stage. Forsetti owns later host discovery, entitlement and activation. Optional profile names, symbols and content cannot rewrite ASH or Core truth.

This contract finalizes the M3 interface; it does not claim runtime acceptance. Acceptance requires the complete28-invariant/five-category executable judgment, per-module failure/no-op/resource proofs and clean unfiltered validation. M4 persistent world/branch/player acceptance and M5 content activation remain separately owned roadmap work.
